# Open-source Higgsfield clones and alternatives (2025-2026, focus on Comfy's #OpenSourceHiggsfield challenge)

Research date: 2026-11-01. Method: `gh search repos` / `gh api` (repo metadata, licence, commit count via the commits Link header, README) plus web search/fetch. No code was cloned or run; every "does it work" claim below is the project's own README claim unless stated. Star counts are as of 2026-11-01 and moving fast. "Commits" is the default-branch commit count.

Licence note: GitHub's API reports `NOASSERTION` for some repos whose LICENSE file is in fact a standard licence. I read the LICENSE file for three such repos: OpenField (MIT), open-higgsfield-skills (MIT), Vision Orchestrator (Apache-2.0). The community list marks OpenField and Vision Orchestrator as "none", which is wrong per their LICENSE files.

## Which open-source Higgsfield clones exist (GitHub, HF Spaces, ComfyUI registry, Reddit/X)?

### Takeaway
There is a large, already-curated field: the CC0 list `jutsuhq/open-source-higgsfield` catalogs 102 challenge projects and 6 older alternatives. The challenge entries are overwhelmingly MIT/Apache, ComfyUI-backed (a custom web front end that drives ComfyUI through the Comfy SDK + `comfy-api-proxy`), open-weights-first (LTX-2.5, MiniMax H3, FLUX 3/2 Klein, Qwen-Image-Edit 2511, Wan 2.2, SAM 3.1, SeedVR2). The pre-challenge "Higgsfield clones" are mostly API front ends (Muapi, kie.ai, Gemini) or take-home-assignment UIs with no models and often no licence.

### Cited Findings

**The challenge itself**
- Comfy's challenge: "Rebuild Higgsfield's popular apps, and more, using ComfyUI"; entries must "Publish your app code with an open-source license and setup instructions"; suggested tracks are Cinematic Studio, Re-shoot a video and Openjutsu; prizes are Best Overall $10,000, Most Innovative / Most Viral / Open Weights Only (RTX 5090 each), 10 runner-ups, plus bonuses for LTX as the core VFX model ($2,000), FLUX 3 as the core model, and MiniMax H3 as the core model. Open Weights Only means "No partner nodes or closed-source APIs." — [comfy.org/open-source-higgsfield](https://comfy.org/open-source-higgsfield); [markdown version](https://comfy.org/open-source-higgsfield.md)
- **Dates conflict.** The live Comfy page (fetched 2026-11-01) says build period "10/15 – 11/3", "Submission window closes: November 3rd 9am PT", winners "11/10", with no mention of an extension — [comfy.org .md](https://comfy.org/open-source-higgsfield.md). The ComfyUI Wiki news item and the jutsuhq list say the deadline was October 30 9am PT and winners November 6 — [ComfyUI Wiki](https://comfyui-wiki.com/en/news/2026-10-15-open-source-higgsfield); [jutsuhq list](https://github.com/jutsuhq/open-source-higgsfield). Most likely the deadline was extended, but I found no source that says so.

This rests on Comfy's own account (an X thread); no Higgsfield statement or letter copy was found — [RuntimeWire](https://runtimewire.com/article/comfy-says-higgsfield-sent-a-48-hour-cease-and-desist-over-open-source-challenge); [explainx commentary](https://explainx.ai/blog/higgsfield-cease-and-desist-comfy-open-source-higgsfield-challenge-48-hours-claimed-vs-verified-2026); list timeline cites [ComfyUI on X](https://x.com/ComfyUI/status/2115928993623109648).
- The Comfy team released its own reference entries: OPENjutsu (character swap, Oct 26) and the clonable `comfy-openjutsu` app template; an earlier `comfy-reshoot` reference app (Sep 29) is the template OPENjutsu says it follows — [jutsuhq list](https://github.com/jutsuhq/open-source-higgsfield); [D3voz/openjutsu README](https://github.com/D3voz/openjutsu); [Comfy-Org/comfy-reshoot](https://github.com/Comfy-Org/comfy-reshoot).

### Inferences
- The challenge converged on one architecture: a purpose-built web UI (Next.js/Vite/React) + a small server that patches committed ComfyUI API-format JSON per job and submits through `@comfyorg/sdk` → `comfy-api-proxy` → ComfyUI. This is structurally close to dw's model (declarative JSON + server + UI), which makes the entries' UX ideas directly portable even where their graphs are not.
- Star counts are dominated by the Comfy team's own entry and by older API front ends; most idea-rich entries have <50 stars and are 1-3 weeks old. "Works" is largely unverified outside each author's own GPU.

### Gaps
- No Hugging Face Spaces or ComfyUI-registry search was done directly (only OpenKatana was confirmed on the registry). HF Spaces for these entries were not found in the search results I ran.
- Reddit threads were not reachable via search; the list links several r/comfyui launch posts (e.g. H3 Recast, Element Forge, RenderRepo) that I did not open.
- Winners are not yet announced (Nov 6 or Nov 10 depending on source).

## How do they structure presets vs fine-grained control?

### Takeaway
The dominant pattern is "named app / one-click preset on top, the real graph one click underneath": a small vocabulary of discrete choices (move, lens, framing, light, stock, grade) that compiles deterministically into the prompt and graph, with an "Advanced" fold and an "open the exact ComfyUI workflow" escape hatch. A few entries reject presets outright in favor of persisted taste state (Boson) or measured verification (Comfy-Dial).

### Cited Findings
- Aither: "A rig is a decision, not a slider stack. `dolly_in` + `85mm` + `close_up` is a different shot from `static` + `85mm` + `close_up`, and the studio makes the model honour the difference — deterministically, in the prompt text"; vocabulary of 20 moves, 7 lenses, 3 speeds, 10 framings, 9 looks; modes keyframe/t2v/i2v/flf2v/reshoot; `plan_shot` compiles a rig into the exact prompt with no render — [Aither README](https://github.com/Aitherium/aither-cinema-studio)
- OpenField's Director: "genre, camera, framing, light, film stock, look, grade, an era scrubber (1960 to 2020) and speed ramps compile into the shot"; Video has "28 motion presets"; every take opens as the exact ComfyUI workflow; user LoRAs are only offered to the model their tensor keys match — [OpenField README](https://github.com/wexloops/openfield)
- CreatorOS "Cinematic Studio: a shot card instead of a prompt. Pick the camera body, lens, focal length and aperture, the framing, the light, the film stock, the look and the grade, add a colour palette (or pull one from a photo)"; 25 one-click camera/effect presets: dolly in/out, jib up/down, side tracking, orbit, arc, crash zoom in/out, bullet time, dolly zoom, plus squish/inflate/cakeify/explode; seven one-click relights; re-shoot angle presets left/right/three-quarter/high/low/sweep/descend/orbit; Library stores "provenance of every render (recipe, seed, LoRAs, final prompt)" and downloads the exact workflow — [CreatorOS README](https://github.com/thePloggy/CreatorOS-Studio)
- OPENjutsu: simple mode is one click; "Advanced" exposes steps, base model, LoRA chain, text-encoder quant, VAEs, motion-reference size (512/768/1376), seed (re-running resumes from last finished clip); `lib/simple.ts` edits the committed API JSON per request by removing/reconnecting nodes (hat fix, no lip-sync) rather than keeping many workflow variants; a preflight checks the workflow against ComfyUI's node and model lists and lists missing packs with install links — [OPENjutsu README](https://github.com/D3voz/openjutsu)
- Parametric Studio: "a form anyone can use, and one click from the exact ComfyUI graph"; apps "Named after what you want to do, not which node to wire"; "Open weights only … enforced by a test" — [Parametric README](https://github.com/parametricparadigm/ComfyUI_Parametric_Studio)
- Boson: "Studios instead of presets: your taste as plain files in git that every next ComfyUI round obeys"; judge a round with green/red dots and one sentence, and "the judgment becomes state the next round must read"; nodes run `stored` (free replay) or `live`; "a studio never names a model" — [Boson README](https://github.com/0xMisterBailey/Boson)
- Continuity: the "pills under the box are the whole setup: duration, aspect, resolution, the model, and a sampler row for when you want it" — [Continuity README](https://github.com/roadmaus/ComfyUI-Continuity)
- Hardware tiers as presets: ReAngle "Hardware detection picks a tier (resolution, chunk length, upscale), refuses under-spec GPUs"; open-higgsfield-skills picks "draft 16 GB / standard 24 GB / max 40 GB"; Picky has preview / turbo HD / 2-pass final quality tiers — [ReAngle](https://github.com/Tekholms-LW/ReAngle); [skills](https://github.com/mojomast/open-higgsfield-skills); [Picky](https://github.com/chenthedesignmaker/ComfyUI-Picky)
- Cost on every control: Haggs shows the credit price "on the Generate button as always" and "Nothing is spent on the drawing page"; Comfy-Dial has a free "Run dry" with synthetic poses and confirms every paid action's credit estimate — [Haggs](https://github.com/IBFolding/haggs); [Comfy-Dial](https://github.com/ylchen333/comfy-dial)
- Open Cinema: physically based lens params (focal length, f-number, focus distance, sensor width) applied after generation from per-frame depth; re-rendering only DoF takes ~7 s; pick-point focus and rack focus — [Open Cinema](https://github.com/LaytonGott/open-cinema)

### Inferences
- The shared design: presets are a closed enum vocabulary compiled into prompt text and graph parameters, not free sliders. That maps cleanly onto dw variables with constrained enums plus a template that injects phrases — the "rig compiles to prompt, inspectable before render" pattern (Aither `plan_shot`) is analogous to dw's free `validate_workflow`.
- "Every output carries its exact recipe/workflow" is near-universal and is a table-stakes expectation (dw manifests already do this).

### Gaps
- Exact preset tables (e.g. Aither's CONTRACT.md, OpenField's 28 motion presets) were not opened; only README summaries were read.

## Which ones include agent/LLM shot planning, storyboard-to-video, multi-shot continuity?

### Takeaway
Many: shot planning by local LLM (OpenField Scene, CreatorOS reel, Motion Previs, OpenReel), script/series compilers (seriesmith), beat-driven music video planners (Mondo, Xenoform), agent skill packs and MCP servers (open-higgsfield-skills, Aither, OpenField 31-tool MCP, OpenKatana, agentY, ComfyArt). Continuity is handled by casts with `@mentions`, hero-frame propagation, last-frame chaining, location references, and automatic QC.

### Cited Findings
- seriesmith: show defined once in `series.json` (cast, places, voices, look), episodes as markdown screenplays → model-free `shotlist/shots.json` → compiled per "video target" → rendered per shot on a backend; "Every shot is its own job, so a bad shot is rendered again alone"; "a shot written `continuous:` reads the take before it when its job starts, so a whole chain still queues at once"; docs include STORY_STRUCTURES (three-act, Story Circle, Kishōtenketsu, Hero's Journey…) and an H3 target doc covering "reference slots, sheets, voices, audio policies, pacing"; its assistant prompt `SKILL.md` is generated from `docs/AUTHORING.md` — [seriesmith README](https://github.com/bgstratt/seriesmith)
- open-higgsfield-skills: `video-director` flow: intake (at most 3 questions) → preflight + tier pick → story-bible → shot-planning (approval gate) → stills → still-qa judge (fail → image-edit / relight / re-prompt / seed+1) → per-shot video → assembly; "records every prompt, seed, model and cost in one resumable JSON manifest"; approval gates "on the bible, the shot plan, spend and stills, and hard caps on retries and GPU-minutes"; chaining via `chain_from: s01` — [skills README](https://github.com/mojomast/open-higgsfield-skills)
- OpenReel's three continuity layers: text anchoring (actor appearance description injected verbatim into every keyframe prompt), image anchoring (first head sheet as reference / first frame for all later generations), plus a unified style block; logline → 8-shot storyboard with framing / camera move / dialogue / duration — [OpenReel README](https://github.com/smithysw7/openreel)
- Shot Board: hero-frame propagation — pick one hero cut, the other five are redrawn from it with Qwen-Image-Edit-2511; save pass/fail verdict with a note; export storyboard + per-cut API workflows + manifest — [Shot Board README](https://github.com/ArcSolver/shot-board)
- Picky: each shot is "a structured document with style, overview, timed beats, camera, dialogue, soundscape and music … composed into MiniMax's official H3 prompt format"; "A prompt linter that knows H3" catches "overfull beats, cuts with no new information, wasted quality tokens, missing soundscape"; cast `@Mara` resolves to the right `<Subject N>` with current references at render time; renaming rewrites every mention; extensions run on the shot's own graph plus Motion Context — [Picky README](https://github.com/chenthedesignmaker/ComfyUI-Picky)
- Mondo Music Video: detects "beats and downbeats, measures energy, and identifies musical sections"; "beat-driven cuts and energy-aware montage grammar"; per-actor beat/drums/bass/vocals assignments for dancing; lyric captions from timed lines — [Mondo README](https://github.com/hodgemann/mondo-music-video)
- Haggs "Recreate an edit": a video model "lists every shot: its length, what the camera sees, the camera move, the words on screen" and rebuilds the edit shot-for-shot around your character; "Draw to video": sketch two kinds of arrows (subject motion vs camera) which are turned into editable plain-language motion text — [Haggs README](https://github.com/IBFolding/haggs)
- CreatorOS: one-click reel where "A local LLM plans 3 to 6 shots of one session (same outfit, place and light)"; driver videos with cuts are split per shot and the montage rebuilt "at the exact original durations"; automatic clip check on CPU in ~1 s: "black frames, frozen video, a jump inside the shot, smear, and how close the face stays to the start image (OpenCV YuNet + SFace)" — [CreatorOS README](https://github.com/thePloggy/CreatorOS-Studio)
- Body Double: long takes as 81-frame segments, each its own job conditioned on the previous segment's last five frames with per-segment seed and colour match; "QC (seam ratio and background drift) runs before the next segment starts, and a flagged segment is re-rolled. Runs resume after a crash" — [Body Double README](https://github.com/lucataco/open-source-higgsfield)
- 360 Scout to Film: one 2:1 equirectangular panorama → overlapping perspective location references (16:9, 2048×1152), a contact sheet, a location/lens prompt and a JSON manifest, shared across every shot; the same refs go to Seedance 2.5 and H3 for comparison — [360 Scout README](https://github.com/Alvinvision/360-Scout-to-Film-Consistency)
- Agent/MCP surfaces: OpenField "31 tools let an agent direct, render, check and finish shots"; Aither exposes `list_camera_moves`, `plan_shot`, `render_shot`, `reshoot_shot`, `grade_shot`, `cut_sequence`, `cut_music_video` (beat sheet from bpm + beats/shot); OpenKatana installs via a copy-paste agent setup prompt that says "Ask before downloading models, spending credits, uploading files or publishing" — [OpenField](https://github.com/wexloops/openfield); [Aither](https://github.com/Aitherium/aither-cinema-studio); [OpenKatana](https://github.com/rk0neki/OpenKatana)
- Vision Orchestrator: chat with an LLM that grows a structured "production blueprint — intent, story, characters, materials, constraints — and only approved content flows into generation" — [Vision Orchestrator README](https://github.com/stellartune-studio/vision-orchestrator)

### Inferences
- seriesmith and Picky are the closest analogues to dw's own `script-to-video` / `series-episodes` skills and H3 prompt tooling; seriesmith's "model-free story → per-target compile" split and Picky's H3 prompt linter are the two most directly comparable designs.
- Automatic, cheap, CPU-side QC between generations (CreatorOS clip check, Body Double seam/drift QC, Comfy-Dial camera verifier, comfyui-sameface face drift) is a recurring idea that dw's `assess_output`/`compare_outputs` partially covers.

### Gaps
- I did not verify whether any of the agent pipelines run end to end; open-higgsfield-skills explicitly says most workflows were only statically checked.

## Which open models do they use for camera control, re-shoot from new angle, character swap, multi-angle stills, lip sync?

### Takeaway
Camera control and re-shoot centre on LTX-2.5 with the Layout-to-Render IC-LoRA fed depth renders/reprojections, CrossView (IC-LoRA for LTX-2.3, LoRA for H3) with MoGe geometry, and the official LTX-2 camera LoRAs / Wan Fun Camera. Character swap centres on MiniMax H3 Ref2VA + SAM 3.1 (OPENjutsu, H3 Recast with BFS LoRA), with SCAIL-2 and Wan 2.2 Animate as alternatives. Multi-angle stills use Qwen-Image-Edit-2511 (+ fal Multiple-Angles LoRA). Lip sync uses H3's native audio, InfiniteTalk, LTX audio-ref tokens, and FaceRefine passes.

### Cited Findings
- **Re-shoot via depth reprojection + LTX IC-LoRA:** ReAngle depth-estimates the clip (Video Depth Anything Small), warps along one global camera path (z-buffered splat), pre-fills revealed holes from the far background, and guides LTX-2.5 distilled via the Layout-to-Render IC-LoRA; long clips are overlapping chunks re-anchored to the warped source frame and LAB colour-matched — [ReAngle](https://github.com/Tekholms-LW/ReAngle)
- **Re-shoot via CrossView:** Comfy's reference app runs MoGe + CrossView Warp + MiniMax H3 + CrossView LoRA — [comfy-reshoot](https://github.com/Comfy-Org/comfy-reshoot); CreatorOS re-shoot uses MoGe-2 + CrossView and keeps original sound — [CreatorOS](https://github.com/thePloggy/CreatorOS-Studio); One-shot Multicam uses LTX-2.3 22B + CrossView IC-LoRA (Apache-2.0) with the prompt being only a camera move ("crossview. new camera angle: far to the right, same height, closer."), and freezes the real audio into the audio latent (`LTXVSetAudioRefTokens`) so generated frame t = source frame t, measured lag 0-1 frames — [One-shot Multicam](https://github.com/apsolut/one-shot-multicam)
- **3D blocking → shot:** OpenField Stage renders a clay clip + exact depth pass in the browser (three.js), paints the look frame on the depth pass with Z-Image Turbo + Fun ControlNet Union, then LTX-2.5 Layout-to-Render IC-LoRA renders a shot "that moves like the blocking" — [OpenField](https://github.com/wexloops/openfield); Comfy-Dial feeds LTX-2.5 a depth video rendered along the authored path ("The model never sees your camera numbers"), recovers the camera per take with Depth Anything 3, scores per third, and repairs only the drifted segment — [Comfy-Dial](https://github.com/ylchen333/comfy-dial)
- **Camera LoRAs:** Open Cinema uses Lightricks' official LTX-2 camera-control LoRAs for static, dolly in/out, truck left/right, crane up/down, and describes other moves in the prompt — [Open Cinema](https://github.com/LaytonGott/open-cinema); open-higgsfield-skills uses Wan Fun Camera with `MOVES: "arc-left-45"` — [skills](https://github.com/mojomast/open-higgsfield-skills)
- **Character swap:** OPENjutsu: SAM 3.1 tracks at 1008 px, mask grown 40 px with 10% headroom, grey-mannequin motion reference, H3 Ref2VA int8 + DMAD 4-step LoRA; Advanced mode labels tracks with Qwen3-VL 8B to map 1-4 characters to roles; known limit: mirrors/reflections leak the original look — [OPENjutsu](https://github.com/D3voz/openjutsu). H3 Recast: H3 + BFS Character Swap LoRA, up to 3 people, scene reference = one edited frame of the clip; "Big, obvious changes land … Subtle ones fall back to the clip" — [H3 Recast](https://github.com/Bambushu/h3-recast). Body Double: SAM 3.1 + FLUX 3 Image Klein first frame + SCAIL-2 with a virtual follow-cam crop so the performer stays large, pasted back into the untouched plate — [Body Double](https://github.com/lucataco/open-source-higgsfield). Wan 2.2 Animate in Swapjutsu/Kawarimi and Wan Animate 2 in CreatorOS — [jutsuhq list](https://github.com/jutsuhq/open-source-higgsfield); [CreatorOS](https://github.com/thePloggy/CreatorOS-Studio)
- **Multi-angle stills / coverage:** Qwen-Image-Edit-2511 with the fal Multiple-Angles LoRA (¾ left/right, profile, from behind, high/low, wide, close-up) in CreatorOS; Qwen-Image-Edit-2511 hero-propagation in Shot Board; OpenField/CreatorOS "Coverage" (wide, ¾, close-up), "Push in", "Next beat" — [CreatorOS](https://github.com/thePloggy/CreatorOS-Studio); [Shot Board](https://github.com/ArcSolver/shot-board); [OpenField](https://github.com/wexloops/openfield)
- **Lip sync / talking:** CreatorOS talking avatar uses InfiniteTalk on Wan 2.1 chained block-by-block to audio length, or LTX-2.5 from typed lines — [CreatorOS](https://github.com/thePloggy/CreatorOS-Studio); OPENjutsu notes H3 lip-syncs any vocals unless "No lip-sync" feeds silent audio, and offers Fix faces "Match the photo" vs "Follow the mouth" — [OPENjutsu](https://github.com/D3voz/openjutsu); H3 Recast's optional FaceRefine lip pass reruns only the face from cache — [H3 Recast](https://github.com/Bambushu/h3-recast); SingSync does "measured lip-sync retime" with Seedance — [gh search](https://github.com/SasanSeyedi/singsync)
- **Licence traps flagged by entries:** Video Depth Anything Base/Large are CC-BY-NC-4.0 (ReAngle defaults to Small); Hunyuan3D 2.1 licence excludes EU/UK/South Korea (Comfy-Dial keeps meshes out of the repo); FLUX.2 marked non-commercial in OpenField; MiniMax H3 community licence has geographic exclusions (Parametric Studio, OpenField "geo-restricted") — [ReAngle](https://github.com/Tekholms-LW/ReAngle); [Comfy-Dial](https://github.com/ylchen333/comfy-dial); [OpenField](https://github.com/wexloops/openfield); [Parametric](https://github.com/parametricparadigm/ComfyUI_Parametric_Studio)

### Inferences
- For dw (diffusers, not ComfyUI), the portable parts are the model choices and the pre/post-processing algorithms (depth reprojection + hole prefill, follow-cam crop + plate paste-back, audio-latent freezing, per-segment chaining with QC), not the graphs. Whether CrossView, Layout-to-Render IC-LoRA, BFS swap LoRA, SCAIL-2 and DMAD LoRA load in diffusers was not checked.

### Gaps
- Did not verify diffusers support for any of these LoRAs/models.
- Lip-sync coverage beyond these few is thin in what I read; dedicated lip-sync entries (e.g. in Haggs' 26 apps) were not inspected.

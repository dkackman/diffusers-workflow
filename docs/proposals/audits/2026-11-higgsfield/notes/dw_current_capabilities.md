# dw (diffusers-workflow) current capabilities for cinematic / animatic / sitcom video, vs a Higgsfield-style feature set

Scope: master working tree at `a2285c64 release 0.17.0`, read 2026-11-01. All sources are repo files (paths relative to the repo root `/Users/don/src/dkackman/diffusers-workflow`) or GitHub issues on `dkackman/diffusers-workflow`. Nothing here was run on a GPU; behaviour claims are what the code/docs/skills state.

## Which templates/workflows exist per shape and per model family?

### Takeaway
dw ships ~110 catalog workflows: 4 video families (MiniMax H3 = 22 templates, LTX-2.5 = 19, Kandinsky 6 = 3, plus a generic Mochi/compose route), FLUX 3 Klein (5) and a dozen FLUX.1/Z-Image/Qwen/SD image templates, plus audio (Music 3, MMAudio SFX, TTS/voice clone) and assembly templates. Shape is not hand-labelled; it is derived from the steps (`image`, `image-set`, `image-edit`, `shot`, `sequence`, `audio`, `text`, `utility`) and filterable over MCP.

### Cited Findings

Traits: `has-audio`, `chained` (a `chain` block or chain args), `image-conditioned`, `identity-referenced` (`references` arg), `composes-workflows`, `needs-input-media` — [dw/server/catalog_shape.py](dw/server/catalog_shape.py) `_derive_shape`/`_derive_traits` (lines ~224-295)

### Inferences
- The family coverage maps well onto Higgsfield's "shot" primitives (T2V, I2V, first/last frame, extend, reference identity, upscale) but every one is a separate template a user/agent must choose; there is no single "shot" UI with a model switch.
- H3 is the only family with dialogue lip-sync and multi-shot-with-cuts templates; LTX-2.5 owns restoration/matte/upscale; Kandinsky 6 is minimal (3 templates).

### Gaps
- No open-weights family for character/face swap, relighting, novel-view/re-shoot, or camera-trajectory control appears in any template or model entry (grep for "relight", "novel view", "reshoot", "face swap", "character swap", "animatic" across docs/plugins/workflows/dw/ui returned 0 files).
- Exact per-template derived shape was not computed at runtime (the server derives it); the per-family shapes above come from skills (`ltx-2.5` says every LTX template is `shot`; `series-episodes` says `dialogue-short`, `music-video`, `assemble-and-score` are `sequence`).

### Inferences
- Edit/assembly is a declarative, re-runnable "recut" job (JSON), not a timeline editor; it is closer to an NLE-as-code than to Higgsfield's in-app editor. Strength: reproducible, measurable (LUFS, seams, sync drift).
- `paste_face_track` + `crop_face_track` + `face-repair` templates give a face-region round-trip that could be the basis of a character-swap/face-replace feature, though none exists.

### Gaps
- No timeline/transition vocabulary beyond hard cut and cross-dissolve (no wipes, J/L-cuts as first-class, titles/captions burn-in task except via the H3 `music-video-subtitle-generator` style pack).
- No colour-match across seams yet (open, parked #1067/#1083/#1033).

## What do the plugin skills instruct agents to do?

### Takeaway
Seven skills: five family pickers (template per request shape + hard rules + cost quote + vendor prompt format) and two cross-cutting orchestrators. `script-to-video` turns prose into a structured shot list (cast, locations, opening/ending state, beat, must_not, join type), casts recurring characters once as shared assets, routes each shot to H3 (dialogue/voice/music) or LTX-2.5 (silent/action/establishing), test-renders, gates on cost, judges with probes, and hands off to `assemble-and-score`. `series-episodes` adds the cross-episode cast lock and the five-beat recut/bed/match_levels/normalize/pair pass.

### Cited Findings
- Plugin inventory: `minimax-h3`, `minimax-music3`, `ltx-2.5`, `kandinsky-6`, `flux3-klein`, `script-to-video`, `series-episodes`; each SKILL.md capped under 12 KB, detail in `references/`, numeric rules pinned by `tests/test_plugin_skills.py` — [plugins/dw/README.md](plugins/dw/README.md)
- script-to-video shot list shape: Cast (voice description, sex, `asset:cast/<name>`), Locations, per shot `opening_state`/`ending_state` (a shot's opening is its source's ending "so the cut between them is written down rather than hoped for"), `beat`, `must_not`, optional `join` ∈ {`continue`, `cut`, `cutaway`, `lead_in`}; user-supplied fields are locked, blanks stay blank — [plugins/dw/skills/script-to-video/SKILL.md](plugins/dw/skills/script-to-video/SKILL.md) step 2
- Routing rule: silent action/establishing -> LTX-2.5 (`text-to-video`, `image-to-video`, chained); dialogue, held voice or scored montage -> H3 `dialogue-short` or `music-video` with `h3-prompt-writing` structure (`subject_definitions`, `retention_analysis`, `detailed_description`, `overall_soundscape`, `non_diegetic_music`); "keep the sharpest of N" -> `best-of-n-to-video` — [plugins/dw/skills/script-to-video/SKILL.md](plugins/dw/skills/script-to-video/SKILL.md) step 4
- Process discipline: test-render 2-4 representative shots; `validate_workflow` and quote `plan.estimate` before `run_workflow`; `acknowledged_cost` "is a real gate ... even when running unattended"; render in source order; 3 failed attempts per shot then ask; after a chain call `assess_output(probe="analyze_seams")`; never splice a re-rolled segment with `concat_videos`; new seed redraws an H3 voice unless pinned by an audio reference (#610) — [plugins/dw/skills/script-to-video/SKILL.md](plugins/dw/skills/script-to-video/SKILL.md) steps 5-6
- Explicitly out of scope: automatic model speed optimisation, authoring new workflows at run time — [plugins/dw/skills/script-to-video/SKILL.md](plugins/dw/skills/script-to-video/SKILL.md) "Not in scope"
- Joins: `cutaway`/`lead_in` are composed from separate runs joined by `concat_videos`; frames taken off a finished shot via `get_last_frame`/`get_first_frame` tasks; "Nothing in a template reads `join`" — [plugins/dw/skills/script-to-video/references/joins.md](plugins/dw/skills/script-to-video/references/joins.md)
- Cast consistency procedure (step 0): draw each portrait (and voice clip) once, `keep_output(..., asset_name="cast/<character>.png", shared=True)`, reference with `from_file` never `from_previous_result`; save portrait and voice description prompts as `prompt:<series>/<character>` and `-voice`; "There is no engine check for 'the same character looks the same' across separate runs; the fixed-asset reference is the only guard" — [plugins/dw/skills/series-episodes/SKILL.md](plugins/dw/skills/series-episodes/SKILL.md)
- Framing guidance (unmeasured): a face small in a wide shot drifts most, frame recurring characters large and keep a wide master — [plugins/dw/skills/script-to-video/SKILL.md](plugins/dw/skills/script-to-video/SKILL.md); [docs/proposals/audits/2026-11-story-forge-lessons.md](docs/proposals/audits/2026-11-story-forge-lessons.md)

- H3 `guides`: up to 4 clips (3 on a guide chain) at frames that are multiples of 17, hold look and motion, `"audio": true` holds the soundtrack — [plugins/dw/skills/minimax-h3/SKILL.md](plugins/dw/skills/minimax-h3/SKILL.md); [docs/WORKFLOW_GUIDE.md](docs/WORKFLOW_GUIDE.md) "H3: holding a clip with `guides`"
- LTX-2.5 caption rules: one 150-220 word paragraph, present progressive, "stating for every shot a shot type, a camera motion (say static when none) and a viewpoint"; multi-shot in one generation = one chronological paragraph naming "a hard cut to", 2-4 shots; voice caption steers pitch/age/gender (measured F0 291/221/136 Hz) but not whisper or tempo — [plugins/dw/skills/ltx-2.5/SKILL.md](plugins/dw/skills/ltx-2.5/SKILL.md) "Prompts"

### Inferences
- The skills already encode much of what Higgsfield sells as product UX (shot planning, cast lock, continuity states, beat review) — but as agent instructions, not UI. Camera/lens vocabulary lives only inside the vendor caption formats (LTX "shot type, camera motion, viewpoint"; H3 Context-IR), not in a dw preset list.

- Kandinsky 6 and Music 3 skill bodies were only skimmed (headings); details not captured here.
- No skill covers storyboard/animatic stills-first pre-vis as a deliverable (FLUX 3 Klein `layout-boxes` and `consistent-set` exist but no skill composes a board).

## What does the MCP surface allow an agent to do end to end?

### Takeaway
65 MCP tools cover discovery (catalog/guides/tasks/pipelines), authoring and validation (free, with cost plan), cost-gated runs, job waiting/events/rerun, media inspection (images, audio, video as frames), automated assessment and comparison, asset/prompt/LoRA/workspace management, model downloads, and export. - No MCP tool for timeline editing per se; assembly is "run another workflow". No vision-based identity check (face similarity across shots) — consistency is judged by eye from frames.

## How is fine-grained control exposed today?

### Takeaway
Control is through workflow JSON (variables with declared constraints, step arguments, pipeline/quantization/acceleration blocks), stored prompts/assets, and a Svelte web UI with a step/flow editor, gallery, assets, compare and job pages. There are no named camera-move or lens presets; camera and shot type are written into the prompt caption.

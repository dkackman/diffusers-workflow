# ui

Guidance for the web UI single-page app. Build and dev setup are in ui/README.md; the look is in the header comment of `src/app.css`; the rules the UI shares with the engine - its response contract among them - are rows in `docs/ARCHITECTURE.md`.

Checks, from `ui/`: `npm run check`, `npm run lint`, `npm test`, and `npx playwright test` (it starts its own server - do not have `dw.serve` on the same port). Server response types come from `src/lib/generated/` - `python scripts/dump_openapi.py` then `npm run gen:api` - never written by hand.

## Rules for new UI

- A workspace's views are `#/ws/<name>/<section>`, listed in `WS_SECTIONS` (`src/lib/routes.ts`), routed in `src/App.svelte` and named in `src/lib/Sidebar.svelte`: overview, workflows, jobs, requests, gallery, compare, assets and edit. A new section goes in all three. **requests** is the workspace's requests ledger: `requests/<id>` is one request, edited only through intents (`src/lib/request/intents.ts`) that `planStore.svelte.ts` applies to the plan as last read when it writes - a plan read earlier is never sent again; what a row shows is derived in `src/lib/request/itemState.ts`, not in a component (`docs/ARCHITECTURE.md`, *Requests in the UI*).
- Show the proof: a list of things that produce images shows the images. Page data is a `resource(load, { watch } | { live })` (`src/lib/resource.svelte.ts`) rendered through `<LoadState>` (only it imports `Empty`); a mutating button is an `action()` / `ActionButton`; an error shown to the user is `describeError`'s copy (`notify.failure`), never `e.message`; the server's state is `connection`, never a page's. Every timer pauses while the tab is hidden and fires once on return, except the app shell's status poll (`src/lib/statusPoll.ts`).
- `--live` marks machine state and `--select` the user's place (focus, the open workspace, the active section), each nothing else; where they may appear is held by `scripts/design-rules.test.ts`. Every token pair should pass WCAG AA in both themes.
- A document editor is a `DocumentEditor` (`src/lib/editorShell.svelte.ts`): its fields sit inside the editor's `root`, whose focused field a flush blurs to commit, or register a flush; saves go through `saveDocument` (`src/lib/documentSave.ts`), nothing else writing a workflow, prompt or upload; leaving while dirty is the router's leave guard (`addLeaveGuard`, `src/lib/router.svelte.ts`), never a per-link handler; a dialog is `chooseDialog`/`confirmDialog` (`src/lib/confirm.svelte.ts`), a destructive choice `danger: true`.

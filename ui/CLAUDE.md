# ui

Guidance for the web UI single-page app. Build and dev setup are in ui/README.md; the look is in the header comment of `src/app.css`; the rules the UI shares with the engine - its response contract among them - are rows in `docs/ARCHITECTURE.md`.

Checks, from `ui/`: `npm run check`, `npm run lint`, `npm test`, and `npx playwright test` (it starts its own server - do not have `dw.serve` on the same port). Server response types come from `src/lib/generated/` - `python scripts/dump_openapi.py` then `npm run gen:api` - never written by hand.

## Rules for new UI

- A workspace's views are `#/ws/<name>/<section>`, listed in `WS_SECTIONS` (`src/lib/routes.ts`), routed in `src/App.svelte` and named in `src/lib/Sidebar.svelte`: overview, workflows, jobs, requests, gallery, compare, assets and edit. A new section goes in all three. **requests** is the workspace's requests ledger: `requests/<id>` is one request, edited only through intents (`src/lib/request/intents.ts`) that `planStore.svelte.ts` applies to the plan as last read when it writes - a plan read earlier is never sent again; what a row shows and what needs the person is derived in `src/lib/request/itemState.ts`, which the server's `needs=true` mirrors, not in a component (ARCHITECTURE, *Requests in the UI*).
- Show the proof, one way: a file is an `OutputTile`, opened in `MediaViewer` (the page's `open` hash), and what made it is a `RecipePanel` (`raw_media` holds the rest at 1); a file or reference to fill in is a `ReferenceField`. Page data is a `resource(load, { watch } | { live })` (`src/lib/resource.svelte.ts`) rendered through `<LoadState>` (only it imports `Empty`), whose quiet reloads keep edits, focus and selection; every mutating button is an `action()`; a destructive one asks or undoes through `src/lib/destructive.ts` (`docs/ARCHITECTURE.md`, *Destructive actions*); a failure toast or load failure is `describeError`'s copy (`notify.failure`, `<LoadState>`), inline, `ErrorLine`, never `e.message`; the server's state is `connection`, fed by every response (`send` in `src/lib/apiRequest.ts`), never a page's. Timers are `poll`'s. `resource` is the only subscriber (ESLint), and `src/lib/freshness.test.ts` holds every page's declaration, resolving a helper one level; a page's own write is `resource().adopt` so it is never marked; every `api` key is classified read or not (`READ_ALIASES`/`NOT_READS` in `scripts/arch-metrics.mjs`, `arch-metrics.test.ts`); an open document watches with `DocumentEditor.watchRemote`.
- `--live` marks machine state and `--select` the user's place (focus, the open workspace, the active section), each nothing else; where they may appear is held by `scripts/design-rules.test.ts`. Every token pair should pass WCAG AA in both themes.
- A document editor is a `DocumentEditor` (`src/lib/editorShell.svelte.ts`): its fields sit inside the editor's `root`, whose focused field a flush blurs to commit, or register a flush; saves go through `saveDocument` (`src/lib/documentSave.ts`), nothing else writing a workflow, prompt or upload; leaving while dirty is the router's leave guard (`addLeaveGuard`, `src/lib/router.svelte.ts`), never a per-link handler; a dialog is `src/lib/confirm.svelte.ts`'s. A page's head is `PageHeader`; copy follows `GLOSSARY.md`, whose banned terms `scripts/copy-rules.test.ts` holds at 0, and its *Before you write markup* table names the piece for each concept.
